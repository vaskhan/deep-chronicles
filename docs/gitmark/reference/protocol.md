# Сетевой протокол

WebSocket, JSON в каждом кадре, различитель — поле `t`. Порт 8790, в проде за nginx
по пути `/ws`. `maxPayload` 8000 байт; текст очищается от управляющих символов и
обрезается до **160 знаков** (`server/server.js:36`), числа зажимаются `num()`.

## Клиент → сервер

| `t` | полезная нагрузка | смысл |
|---|---|---|
| `register` | `{name, pass, cls}` | от клиента берётся **только класс**, персонажа строит сервер |
| `login` | `{name, pass}` | вход по паролю |
| `auth` | `{token}` | вход по токену устройства; под лимит попыток **не попадает** |
| `logout` | `{token}` | удаляет строку токена |
| `st` | `{x, y, z, r, a}` | положение и битовая маска действия, 10 раз в секунду; лимит 25/с |
| `atk` | `{id, kind:'p'\|'m', hold?}` | цель; `hold:true` — только взять на прицел; `id:null` — сбросить |
| `skill` | `{id}` | применить изученный ранг умения |
| `learn` | `{id,rank}` | изучить строго следующий ранг за SP, сохранить сразу |
| `prof` | `{id}` | выбрать профессию с 20 уровня: класс, повтор и частота (1 с) проверяются сервером |
| `autoloot` | `{enabled:boolean}` | переключить серверный автолут и сохранить |
| `craft` | `{id,request}` | изготовить вещь рядом с торговцем; request — уникальный ID заказа |
| `pickup` | `{id}` | подбор серверного объекта добычи: жизнь, 3 м, защита владельца, атомарная выдача |
| `use` | `{id}` | зелье или свиток побега |
| `equip` | `{idx, slot?}` / `unequip {slot}` | надеть/снять |
| `buy` | `{id, n}` / `sell {idx, n}` | торговец, радиус 8 м |
| `ench` | `{scroll, ref: {bag:idx}\|{slot:id}}` | заточка |
| `tp` | `{id}` | телепорт у привратника; сервер задает позицию; проверка скорости остается включенной |
| `respawn` | — | возрождение |
| `wash` | — | смыть карму у жреца |
| `chat` | `{ch:'all'\|'trade'\|'near', text}` | кулдауны 3000 / 10000 / 800 мс |
| `pm` | `{to, text}` | личное сообщение, кулдаун 400 мс |
| `dev` | `{x,z,coins,lvl,hp,item,n,xp,sp,drop}` | **только** при `DEV_CMD=1`; в проде отсутствует |

## Сервер → клиент

| `t` | полезная нагрузка | когда |
|---|---|---|
| `hi` | `{online, features:{groundLoot:1,progression:1,autoloot:1,crafting:1,nativeOnly:1,professions:1,timedEffects:1,eliteMobs:1,mobPacks:1}}` | сразу после соединения (по нему же работает проба `server_probe.gd`) |
| `authok` | `{id, name, token, p, online}` | успешный вход; `p` — профиль целиком |
| `autherr` | `{reason, kind}` | `kind:"auth"` — клиент забывает токен |
| `kicked` | — | этим аккаунтом вошли в другом месте; клиент останавливает цикл |
| `you` | `{p}` | профиль целиком, когда он изменился (`a.dirty`) |
| `snap` | `{ts, o[], m[], g[], me{}}` | каждый тик, см. ниже |
| `ev` | `{e:[…]}` | пачка боевых событий за тик |
| `mobs` | `{n:[[id, kind], …]}` или `[[id, kind, rank, name, size]]` | виды впервые увиденных мобов; элита и чемпион приходят расширенной строкой |
| `look` | `{id, name, look}` | внешний вид игрока при первом появлении и при смене экипировки |
| `fix` | `{x, z}` | откат: сервер не поверил скорости |
| `me` | `{karma, pk, pvp, flag}` | изменился PvP-статус |
| `leave` | `{id}` | игрок ушёл из видимости/из игры |
| `online` | `{n}` | счётчик онлайна |
| `announce` | `{text, pk?}` | общесерверное объявление |
| `chat` | `{ch, from, id, text}` · `pm {from, to, text}` | чат и личка |
| `chatwait` | `{ch, wait}` · `pmerr {to, reason}` | кулдаун и ошибка лички |
| `washok`/`washerr` | `{cost}` | смывание кармы |
| `pickup_err` | `{id, reason}` | отказ подбора без изменения профиля |
| `pvperr` | — | PvP запрещён (город) |

### Снапшот

Радиус `VIEW = 220` м, координаты округлены до 2 знаков.

- `o` — игроки: `[id, x, y, z, r, anim, hpPct, status]`, где `status` — `0` белый, `1` фиолетовый
  (активен флаг), `2` красный (карма > 0).
- `m` — мобы: `[id, x, y, z, r, flags, hpPct, ageMs]`, флаги — битовая маска
  `1 = идёт, 2 = бьёт, 8 = мёртв`. Восьмой столбец `ageMs` — возраст смерти: по нему клиент
  держит и растворяет тело (`CORPSE` в `src/sim.js`, `server/sim/mobs.js`), у живого моба он
  равен нулю. Клиент читает ещё бит `4 = кастует` (`actor.gd`).
  Девятый столбец добавляется **только если на цели есть эффекты во времени**:
  `[[id, kind, осталось мс], …]`. У игроков он стоит на том же месте, после `status` —
  поэтому PvP-статус читается по индексу 7 только у игроков, а у мобов там возраст смерти.
- `g` — полный список наземной добычи в видимости: `{id,item,n,x,y,z,ownerName,protectedUntil,expiresAt,available}`. Отсутствующие в следующем снимке ID удаляются с экрана.
- `me` — своё: `{hp, mp, x, z, dead}` плюс `fx: [[id, kind, осталось мс], …]`, когда на герое есть эффекты во времени.
- `ts` — серверное время; по нему клиент оценивает сдвиг часов и рисует чужих на 150 мс в прошлом.

### События в `ev`

`hit {m|p, dmg, crit, dot?, by?}` · `miss` · `mdie` · `hurt {dmg, crit?, dot?, dodge?, from|fromP, name, guard?}` ·
`heal {kind, amount, skill?, hot?, drain?}` · `cd {id, cd}` · `cast {id, t}` · `cast_fx {id, to?}` ·
`buff {id, dur, stat, mul}` · `fx {id, kind, up, dur?, m|p}` ·
`loot {id}` · `kill {mob, name, xp, sp, coins, ground, boss}` · `pickup {id, item, n}` · `lvl {lvl}` ·
`dead {by, loss, pk}` · `move {x, z}` · `ench {ok, color}` · `msg {text, cls}` (`cls` ∈ good/bad/rare).

`fx` — наложение (`up:true`, `dur` — реальный остаток в мс) и спад (`up:false`) эффекта во
времени. `kind` ∈ `buff` / `debuff` / `slow` / `dot` / `hot` / `drain`; `id` — «умение» или
«умение:вид», чтобы одно умение могло держать на цели несколько разных эффектов. Событие
видят все в радиусе `VIEW`, включая носителя. `hit {dot:1}` и `hurt {dot:1}` — тик урона со
временем: клиент не проигрывает по нему замах и удар. `heal {hot:1}` — тик лечения со
временем, `heal {drain:1}` — возврат здоровья вампиризмом. Сила, длительность и сам урон
считаются только на сервере (`src/effects.js`), клиент рисует значок и ауру.

`pushNear` (`server/server.js:389-392`) дублирует событие всем в радиусе `VIEW`, дописывая
`by: actorId` — так соседи видят чужой бой.

В профиле добавлены `sp`, `skills: {id:rank}`, `prof` (профессия или `null`), `autoloot` и последние 32 `craftReceipts`; миграция сохраняет v3 и старые вещи. Умения профессии попадают в `skills` только после `prof` и обычного `learn`. При `kill.ground:false` сервер уже выдал автолут и сохранил его; `pickup.id` у такой награды пустой. При `kill.ground:true` опыт и SP уже выданы, а монеты/вещи ещё лежат на земле. Зачисление происходит только после `pickup` и серверного `you`. Получение награды сразу сохраняется в SQLite, при неудаче записи предмет возвращается на землю. Право привязано к аккаунту на 20 с, затем подбор общий, исчезновение через 5 минут; неподнятая добыча не переживает рестарт. Источник чисел — `src/loot.js`. Полное описание: [GROUND_LOOT](docs/GROUND_LOOT.md).

## Что важно помнить

- **Профиль всегда целиком.** Дельт нет — поэтому рассинхрона профиля не бывает.
- **Внешний вид собирает сервер** из экипировки (`lookOf`, `server/server.js:42-50`):
  `{cls, lvl, w, staff, ench, body, robe, mat, gear{…}}`. Добавил новый вид — добавь поле там.
- **Идентификатор игрока — номер соединения**, он новый после каждого реконнекта. Личка при
  этом ищет собеседника по ключу аккаунта (`server/server.js:367`) — это разные пространства имён.
- **Допуск `LAG_M = 4` м** к дистанции удара: клиент видит мир на ~250 мс в прошлом.
- **Эффекты во времени не суммируются**: повторное наложение того же `id` продлевает срок и
  обновляет силу, второй экземпляр не появляется. Замедление сервер накладывает только на
  мобов: движение игрока ведёт клиент, и урезанная скорость вызвала бы ложный `fix`.
- **Ранг моба считает сервер.** Клиент не вычисляет множители элит: он получает готовые
  `rank`, `name` и `size` в `mobs` и рисует по ним подпись, размер и ауру.
- Добавил команду клиента — добавь в [`tests/server.test.js`](tests/server.test.js) проверку,
  что её нельзя подделать.

## Heartbeat и вытеснение сессии

`hi.features.heartbeat = 1` разрешает JSON `ping` → `pong` каждые 10 секунд до и после входа. Сервер ограничивает ответ одним в секунду. Старые серверы без feature-флага не обязаны отвечать; у неавторизованного клиента без heartbeat нет искусственного таймаута простоя.

Вход тем же аккаунтом отправляет прежнему клиенту `kicked` и закрывает WebSocket кодом **4001** (`session replaced`). Клиент читает оставшиеся пакеты даже при CLOSING/CLOSED; код 4001 означает остановку автоматического переподключения и постоянное сообщение на экране входа. Повторный вход — только по действию пользователя. Обычный сетевой сбой восстанавливает токен и сохраняет историю чата.
# Боевые визуальные события и публичный онлайн (18.09.2026)

- `ev: cast {id,t}` — собственная подготовка заклинания. `ev: cast_start {id,t,by}` — подготовка соседа в радиусе VIEW. Старые сборки игнорируют новый тип и не блокируют собственную ходьбу. Время t вычисляет сервер с учётом скорости каста.
- `ev: cast_fx {id,to?,by?}` — подтверждённый выпуск, теперь также для лечения и баффа; точные HP и бонусы по-прежнему в своих `heal`/`buff`/`you`/`snap`.
- `online {n}` после входа/выхода доступен также неавторизованному экрану входа. n — число авторизованных игроков; WebSocket посетителя сайта или клиента на входе в него не входит. Другие broadcast-сообщения продолжают требовать авторизацию.

### Читаемый бой (combatTelegraphs: 1)

`attack_start {t,to}` — начало собственной автоатаки до серверного попадания, у соседей содержит `by`. `attack_release {to}` подтверждает выпуск автоатаки (у соседей также `by`) и запускает снаряд мага; урон рассчитывает сервер. Старые клиенты могут игнорировать новые события. `mob_windup {m,p,t,x,z,r,reach,arc}` — фиксированный сектор замаха, `mob_strike` с теми же параметрами и `landed` — проверка позиции жертвы сервером, `mob_cancel` — отмена при потере цели. `landed` означает попадание в геометрию сектора: отдельный обычный бросок уклонения ещё может дать `hurt {dodge:true,from}`. `hurt` и награды по-прежнему авторитетны, сектор не даёт AoE-урон соседним игрокам.
