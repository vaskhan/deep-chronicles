# Воспроизводимый конвейер нативной игры

Этот документ описывает конвейер Godot. Миграция на UE5 свёрнута 21.09.2026, её наработки
удалены; действующие команды ниже — единственный рабочий путь. Текущий checkpoint охоты/пати
не прошёл полный release; состояние проверок — в начале [CURRENT_TASKS.md](CURRENT_TASKS.md).

## Линтер сцены и файл настраиваемых чисел

`npm run native:lint` (runner `godot/tests/scene_lint.gd`, флаг `--scene-lint`) строит мир
headless и ищет молчаливые дефекты графики: вывернутые нормали (сравнение нормали вершины
с нормалью треугольника при обходе по часовой стрелке), ненормализованные нормали, меши без
поверхностей и материалов, пустой AABB, NaN и нулевой/отрицательный масштаб, отсутствие или
выключенность `Sun`, солнце, светящее вверх, отсутствие `WorldEnvironment`, объекты под рельефом.
Отчёт — `.native-run/scene-lint.log`, строка `SCENE_LINT` с числами, признак успеха
`SCENE_LINT_OK failures=0`. `--strict` приравнивает предупреждения к ошибкам.
Линтер проверен мутациями: выключенное солнце и инвертированные нормали террейна дают отказ
(401 ошибка), чистая сцена — ноль.

Все настраиваемые числа клиента лежат в `godot/scripts/tuning.gd` (автозагрузка `Tuning`),
литералами по одному на строку, чтобы правка не требовала поиска по коду. `tests/tuning.test.js`
проверяет литеральность, использование каждой константы, согласованность пределов камеры и
отсутствие дублей чисел в `main.gd`. Правила боя и наград в этот файл не переносятся.

Действующий клиент — самостоятельное приложение Godot. Пользователю приложения не нужны Node.js, браузер, исходники или редактор: ресурсы встроены в экспорт, аккаунт и прогресс приходят с `wss://realms.neuraldeep.ru/ws`. Node.js нужен разработчику для экспорта общих данных, тестов и отдельного игрового сервера.

## Повторить сборку из исходников

Нужны Node.js **22.23.1** (`.nvmrc`), Godot **4.7.2 stable** и export templates той же версии. Путь к движку задаётся `GODOT_BIN`, если он не найден автоматически. На macOS используется Metal; на CI можно запускать без дисплея.

```sh
npm ci
npm run native:verify -- --release
# Другие варианты:
npm run native:verify -- --build=windows
npm run native:verify -- --headless --offline
npm run test:native -- --touch
```

Конвейер последовательно выполняет:

1. Тесты общих правил JS и сервера.
2. Экспорт каталогов, цен продажи, правил заточки, мира, коллизий, иконок и резервных анимаций из `src/` / `public/assets/`.
3. Импорт ресурсов в Godot.
4. Запуск **нашего Node-сервера и нашего Godot-клиента** с отдельной временной SQLite-БД. UI отправляет настоящие команды: покупка, продажа стопки, экипировка, заточка, умения, бой, телепорт, чат, ЛС, выход и восстановление по токену. Второй клиент проверяет совместимость протокола, присутствие игроков и чат. Проверяются все окна, серверные метки миникарты, баффы и смена модели оружия.
5. Проверку крепления оружия к скелету в шести позах. При наличии дисплея — контрольный снимок.
6. Подключение **из Godot** к основному серверу по TLS и проверку приветствия `hi`. Этот шаг не входит в аккаунты и не меняет данные игроков. `--offline` явно отключает его; это не считается подтверждением доступности основного сервера.
7. Экспорт выбранной платформы, если указан `--build=…`.

Ошибки GDScript, провал тестов, подключения или сборки останавливают конвейер. Результат: `.native-run/verification/report.json` — commit, состояние рабочей копии, версии, команды, длительности, успех шагов и SHA-256 входов/результатов. Логи рядом, снимки окон в `.native-run/test-artifacts/`, сенсорного режима — `.native-run/test-touch-artifacts/`. Отчёт следующего прогона заменяет предыдущий; архивируйте каталог для хранения истории сборок.

Результаты экспорта:

- macOS: `godot/builds/macos/Хроники Глубин.app` и ZIP.
- Windows: `godot/builds/windows/Хроники Глубин.exe` со встроенным PCK и `khroniki-glubin-windows.zip` (EXE, README, SHA256). Для упаковки требуется Python 3; порядок и даты ZIP зафиксированы.
- Android: `npm run native:verify -- --build=android --debug`; нужны Android SDK/JDK.
- iOS: `npm run native:verify -- --build=ios`; нужны Xcode, Apple team и подпись.

Проверка сенсорного интерфейса на компьютере не заменяет запуск на Android/iPhone. Подпись, упаковочные метаданные и версии импортёров могут менять байты архива: здесь воспроизводятся процесс и игровой результат, а побайтовая идентичность ZIP не заявляется.

## Запуск и серверные данные

```sh
npm run dev                                     # основной сервер, вход в существующий аккаунт
npm run native:local                            # отдельный локальный мир и персонаж
npm run native -- --built --skip-assets          # готовое macOS-приложение
npm run native:probe                            # проверка основного сервера без входа
npm run native -- --server=ws://127.0.0.1:8790    # явный адрес сервера
```

Серверная учётная запись совпадает с браузерной: войдите тем же именем и паролем непосредственно в игре. Локальный персонаж не является персонажем основного сервера. Клиент не переносит локальную SQLite-БД в продакшен. Обычный запуск не создаёт случайных аккаунтов на основном сервере.

Токены хранятся раздельно по адресу сервера в Godot `user://sessions.json`; старый `session.json` переносится при сохранении. Пароли не сохраняются. Настройки чата находятся в `user://interface.cfg`. В `--test-mode` эти пользовательские файлы не читаются и не записываются. Тестовые БД удаляются после прогона; обычная локальная БД — `.native-run/world.db`. `DEV_CMD` разрешён только в тестах.

Для проверки конкретного существующего персонажа нужен обычный вход пользователя в окно приложения. Проверка TLS без входа не подтверждает состояние его аккаунта. Нового развёртывания сервера для этих меню не требуется: используется действующий протокол.

## Графика и регрессии

Готовые GLB и текстуры в `godot/assets/` — версионируемые входы сборки. Их не надо повторно генерировать AI при каждом запуске. Происхождение, концепты и команды генерации описаны в `art/README.md`; запросы текстур — `art/imagegen-prompts.json`. AI-генерация не гарантирует побайтового повторения, поэтому принятый результат хранится в git.

```sh
npm run native:assets
npm run native:art -- warrior_cloth              # подготовка исходного TRELLIS GLB в Blender
npm run native:gallery -- --models=warrior,mage,wolf
npm run native:weapons -- --output=/tmp/weapons.png
```

`native:art` требует Blender и исходный `tools/models-out/<id>.glb`; эти тяжёлые промежуточные файлы не нужны для обычной сборки из git. Нельзя вручную править `godot/generated/`. Положение хвата задаёт `actor.gd`: `BoneAttachment3D` → `WeaponGrip` → оружие; оси сверяются с каноническим скелетом, центр рукояти совмещается с ладонью, размер не зависит от варианта брони. `weapons.gd` проверяет запястье, центр рукояти и направление клинка в покое, беге и атаке.

Миникарта читает живые снимки сервера, скрывает мёртвых и устаревших акторов. Она не подставляет точки из каталога спавнов. Все команды окон подтверждаются сервером; покупки, заточка и прогресс не применяются оптимистически на клиенте.

После изменения: выполнить подходящий конвейер, осмотреть снимки, открыть собранное приложение, проверить реальное подключение и обновить `AGENTS.md` / `CLAUDE.md`, если изменился порядок работы. Выкладка сервера и синхронизация публичного репозитория — отдельные операции.

## Полный релиз: только Godot и сайт скачивания

`npm run native:verify -- --release` проверяет общие правила и SP/крафт, отдельный Node-сервер + Godot, крепление оружия, TLS к основному серверу, расчёт экономики, экспорт macOS и Windows, упаковку EXE в ZIP, затем `site:build` и `test:site`. Последний тест запускает headless Chromium только для страницы скачивания: онлайн приходит с отдельного настоящего сервера, проверяются ссылки и SHA-256, отсутствие игрового canvas, настольная/мобильная верстка. Обычный браузер пользователя не открывается.

Браузерная игра больше не поддерживается. Старый флаг `--web` отклоняется. Общие JS-модули нужны серверу и экспорту; не удаляйте их как браузерный мусор.

`npm run deploy` запускает полный прогон перед выкладкой. `npm run deploy -- --verified` проверяет все хеши входов/результатов успешного отчёта; изменения после проверки требуют нового прогона.

Релиз сначала загружается в `/opt/realms/releases/<commit-time>/`; зависимости устанавливаются до остановки мира. Затем сохраняется предыдущий код, останавливается служба, делается SQLite-копия на сервере, заменяются код/статика и запускается служба. При ошибке код откатывается. Рабочая БД не копируется с компьютера и не заменяется при откате. Проверяется локальное приветствие с `groundLoot:1`, `progression:1`, `nativeOnly:1` и внешний TLS из Godot. Журнал `.native-run/deployment.json` создаётся только при успехе. Адрес SSH берётся из `DEPLOY_HOST` и не печатается.

`npm run test:native -- --touch` проверяет увеличенную раскладку. Native smoke включает отдельные журналы, настоящую прокрутку UI без движения камеры, масштаб миникарты, настройку панели, SP/обучение/крафт, подбор с подходом, второй клиент и B-комплект мага. Снимки сохраняются в `.native-run/test-artifacts/` и `test-touch-artifacts/`. Это не тест на физических Android/iPhone/Windows.

`npm run native:economy -- --write` обновляет детерминированный расчёт в `docs/ECONOMY_BALANCE.md`; обычный запуск пишет только `.native-run`. `npm run native:references` восстанавливает референсы C4 с проверкой хешей.

## Чистая машина и CI

`npm run native:bootstrap` устанавливает закреплённый Godot 4.7.2 и настольные шаблоны из официального godot-builds, проверяя SHA-512 из `tools/godot/toolchain.json`. Нужен Python 3; macOS использует ditto. Скрипт печатает GODOT_BIN и в GitHub Actions записывает его в окружение. Мобильные SDK/шаблоны этим способом не устанавливаются.

GitHub workflow `.github/workflows/native.yml` проверяет Windows и macOS: правила, pipeline contract, сервер, Godot без дисплея, экспорт, затем `test:native -- --headless --built` с настоящим локальным сервером и 65-секундный анонимный TLS probe собранного клиента. Это проверка исполнения на ОС, но не ручная проверка видеодрайвера/интерфейса пользователя.

Контракт релиза включает весь набор входных файлов: добавление нового GDScript после проверки теперь тоже блокирует выкладку. Отчёт с изменявшимися во время тестов исходниками отклоняется. Манифест обязан совпадать с commit, размерами и SHA ZIP. Неизвестные флаги и сочетание --release с --build/--debug отклоняются до тестов.

## Диагностика переподключений

Звук и эффекты первого боевого прохода: `docs/ART_AND_COMBAT_DIRECTION.md`. `npm run native:audio` воспроизводит 13 WAV, `native:audio -- --check` включён в verify как `audio-assets`. Исходные звуки коммитятся; при запуске клиента ничего генерировать не нужно. Native smoke проверяет чужой/свой каст, подтверждённый выпуск, реальные звуковые узлы и громкость, огонь/лёд, лимиты и очистку. Кадры `combat-casting.png`, `combat-frost.png`, `combat-fire.png` сохраняются вместе с UI-снимками.

Онлайн на входе и в HUD считается по авторизованным игрокам. Неавторизованные подключения получают только `hi` и изменение `online`; чат, профили и бой им не рассылаются. При обрыве клиент показывает отсутствие связи, а не старое число.

Настройки → «Открыть сетевой журнал»: `user://network.jsonl`, на Windows `%APPDATA%/Godot/app_userdata/Хроники Глубин/network.jsonl`. Записываются события/код/время жизни соединения; данные входа и переписка не пишутся. Возврат в окно сначала опрашивает старый сокет. Протокол `ping` → `pong` работает до и после входа; `hi.features.heartbeat=1`. Сбой сети не стирает чат и несданный черновик.

Полный `--release` теперь также требует `touch-client-server` и `packaged-client`. Встроенный диагностический режим `--test-mode --self-test` работает только с явно заданным loopback-сервером. Релизные templates не поддерживают прежний запуск через --script/--path: проверяется та же упакованная игра через точку входа main.gd. `--network-probe` использует непосредственно Network, не отдельную реализацию транспорта, и не авторизуется. macOS + Windows общий выпуск выполняется на macOS; на Windows доступен --build=windows.

Текстовые входы используют LF из `.gitattributes`; это предотвращает изменение CRLF→LF при импорте на Windows. При иных изменениях verify выводит список изменённых файлов, а не пропускает дрейф. Общий процесс сборки повторяем, побайтовая идентичность разных ОС не обещается.

## Проверки восстановления персонажа и переноса

`npm run test:unit` проверяет сохранение смерти и нулевых HP/MP, совместимость старых v3-профилей и обычное возрождение. `npm run test:server` проверяет передачу последнего состояния между устройствами по паролю и токену, отказ произвольному перемещению после неудачного телепорта/возрождения живого героя, а также законный перенос и последующее движение. Проверки используют временную локальную БД.

После серверного переноса проверка скорости не отключается: клиент принимает новую позицию, а запоздавшие координаты корректируются кадром `fix`. Запас допустимого пути пополняется по серверному времени со скоростью персонажа, ограничен 0,5 секунды и не увеличивается от частоты пакетов. После входа/переноса однократно допускаются 0,15 секунды движения. Поиск пути остаётся отдельным этапом.


## Серверная проверка движения

Кадр `st` может содержать `path: [{x,z}, ...]` — до 64 промежуточных точек, последняя совпадает с `x,z` кадра. Проверяется полная длина маршрута и каждый отрезок относительно препятствий мира и неподвижных NPC. Без `path` проверяется прямой отрезок. Пакет применяется целиком либо возвращается `fix`; высоту вычисляет сервер. Начальная позиция внутри препятствия допускает только выход наружу. Радиус персонажа — 0,6 м, допуск поверхности — 0,02 м.

Godot передаёт шаги локального движения длиной до 0,25 м, чтобы обход края препятствия не выглядел срезанием угла между сетевыми кадрами. Перед применением навыка и подбором отправляется накопленный путь; перенос/коррекция очищает его. Клиент и сервер желательно обновлять вместе: старый клиент без промежуточных точек может получать коррекции при обходе препятствий.

`tests/movement.test.js` проверяет частоту пакетов, накопление запаса, диагонали, некорректные маршруты, коллизии, каст, смерть и перенос. Сетевой тест проверяет отказ срезанию фонтана и сохранение принятой позиции после обхода. Native smoke проверяет обход фонтана настоящим клиентом без `fix`. Это проверки круговых препятствий из данных мира, не коллизий произвольной визуальной геометрии и не навигации мобов.

## Движение и звук, второй проход

`native:audio -- --check` теперь проверяет 67 закреплённых CC0-файлов; `--fetch` восстанавливает источники, `--analyze` измеряет LUFS/true peak через ffmpeg. Источники существ закреплены в `art/sources/creatures`, локальная пересборка `native:art -- wolf rabbit boar spider scorpion`. `native:gallery -- --models=warrior,wolf,boar --clip=run --phase=0.22 --output=/tmp/run.png` даёт повторяемую позу.

Native smoke проверяет настоящее движение/скелет/шаги, Tab/Q, декодирование банка, музыку и ducking, серверный замах и выход из его сектора. Только рендерный запуск проверяет выход AudioEffectCapture, headless проверяет маршрутизацию/ресурсы. Оружейный тест — 10 поз (idle/walk/run/attack/cast_enter у двух классов). Клиентские и серверные журналы сохраняются отдельно, предупреждения Godot считаются отказом.

Показ нового интерфейса: `npm run native:local -- --skip-assets --panel=inventory --capture=/абсолютный/путь/ui.png`. CLI открывает сумку только после серверного входа; JSON рядом со снимком содержит окно и состояние музыки. Локальные аккаунты не переносятся на основной сервер. Новые рамки и пиктограммы — текстовые SVG в `godot/assets/ui/`, пустые слоты рисует `item_slot.gd`; никаких ручных операций в редакторе для воспроизведения не требуется.

## Охота / группы / материалы

Актуальная спецификация: [FARMING_AND_PARTY.md](FARMING_AND_PARTY.md). В обязательном конвейере добавлены `material-assets` (9 CC0 PBR-карт с SHA-256), `scales` (19 тел + 2 вида добычи), unit-тесты групп и реальный WS/Godot сценарий пати. Оружие проверяется в 12 позах, включая второй удар. Все новые материалы, игровые данные и инструменты входят в хеши релиза.

Для индивидуальной выдачи экипировки: `node --no-warnings tools/admin/grant-gear.mjs --db=/server/path/world.db --names=... --level=25` показывает изменения без записи. Применение требует остановить службу, затем `--apply --offline`, после чего запустить службу. Инструмент делает локальную для сервера SQLite-копию перед транзакцией, сохраняет прежние надетые вещи и не трогает пароли/токены/чужие аккаунты. Базы/резервные копии и результаты персональных операций не коммитятся. Не применять к запущенному миру.

Новые источники и ограничения перечислены в `art/README.md`. Деревья и кусты пересобираются локально: `blender --background --python tools/godot/build-botanical.py`; только кусты — добавить `-- --shrubs-only`. Перед этим нужен обычный экспорт данных, который создаёт собственную текстуру коры. Затем выполнить штатный импорт Godot. Геометрия и `.import` закрепляются в репозитории.

Обзор локаций без аккаунтов: `Godot --path godot --script res://tests/landscape.gd -- --test-mode --server=ws://127.0.0.1:8790 --output=/tmp/landscape`. Это отдельные кадры окружения, не подмена игровых скриншотов с HUD. Обычный локальный клиент: `npm run native:local -- --skip-assets`. Этот сценарий только снимает кадры и не меняет аккаунты или прогресс.
Громовое ущелье без сервера: `Godot --path godot --script res://tests/gorge_review.gd -- --test-mode --output=/tmp/gorge` — общий план с водопадом, водопад, террасы, гроты, вершина. Кадры ущелья с интерфейсом (прибытие, элита, стая, водопад) пишет `npm run test:native` в `test-artifacts/gorge-*.png`.

Раскадровка бега: `Godot --path godot --script res://tests/gait_storyboard.gd -- --test-mode --output=/tmp/gait`. Скрипт ведёт настоящего героя по лугу с серверной скоростью, снимает восемь кадров подряд за один цикл бега и печатает `GAIT_STORYBOARD` с проскальзыванием опорной ступни в мире (`--trace` добавляет покадровые отсчёты). Это проверка походки, а не замена smoke-теста: сервера и аккаунтов он не трогает.

Темп движения по последующему запросу пользователя повышен на 10%: `MOVE_SCALE=0.275`, воин 7.15 м/с, маг 6.3624 м/с без модификаторов; обычный моб 3.3 м/с. Каденс анимации по-прежнему вычисляется из фактического перемещения в `actor.gd`, без отдельного визуального ускорителя. Для локального просмотра требуется перезапуск сервера после экспорта каталога.

### Компактные города и PvE

Городской план масштабируется по X/Z до 80%: одна трансформация world-core применяется к геометрии, препятствиям и NPC; тот же scale экспортируется для декора, карты и растительности. Рельеф гавани вычисляется в координатах плана. Жилые дома имеют два этажа, крутые крыши, небольшие тёмные окна, усиленный фахверк и неоднородную штукатурку.

Канонические скелеты используют Jog_Fwd вместо низкого спринта Sprint; скорость клипа синхронизируется с перемещением по опорной скорости 5.27730 м/с до масштабирования модели.

Из браузерного PR перенесены только правила погони и восстановления: 180 м от дома для обычных мобов, 140 м для боссов, разрыв 220 м до цели. Возврат не лечит. Через 5 секунд после возвращения в спокойное состояние, не дальше 8 м от дома, восстанавливается 2% HP/сек. Агрессия прерывает лечение и не затирается таймером прогулки; замах отменяется при превышении дистанции.

Воин (ткань и кольчуга): геометрия голеней/сапог выровнена относительно канонического скелета через `tools/godot/align-human-legs.py`. Вход — оригинальный rigged GLB до коррекции; скрипт не надо повторно применять к исправленному файлу. UV, веса и скелет сохранены.

Смерть мобов: нелупящаяся анимация падения, 5 секунд неподвижного тела после клипа, затем 1.5 секунды прозрачности. Индивидуальные копии материалов не затрагивают живых мобов; при возрождении исходные материалы восстанавливаются. Сервер держит тело 12 секунд и передаёт возраст смерти в поле 8 снимка — входящий в область игрок видит правильную фазу, а не новое падение.

Автоатака: базовый aspd обоих классов уменьшен на 20%, полный цикл взмаха — 88% интервала, урон на 35% взмаха; сервер объявляет длительность клиенту. Дневной небосвод насыщеннее, влияние тумана на небо отключено, дальняя дымка ослаблена по регионам.

Интеграция с upstream `279ac69`: сохранены пати/чат/материалы и план UE5. Стартовые охотничьи группы перенесены к западному и северному выходам, чтобы не попадать в увеличенный относительно старого upstream план гавани/акваторию; тесты используют координаты общего каталога. Фасады и мощение используют CC0-карты upstream. Насыщенная природная палитра и малый туман соответствуют отдельному запросу этой итерации.

## Воспроизведение художественного среза ущелья

- `npm run native:gorge-assets` проверяет 21 закреплённый файл, SHA-256, CC0-источник, mipmaps карт и включённый импорт LOD моделей; `npm run native:audio -- --check` — отдельный банк с записью водопада CC-BY-3.0 и атрибуцией.
- Исходные URL и MD5 glTF 1K с зависимостями закреплены в `godot/assets/gorge/manifest.json::sources.*.original_gltf_1k`. Сохранить glTF как `<slug>.gltf`, его `include` — с исходными относительными именами. Подготовка: `blender -b --python tools/godot/prepare-gorge.py -- /путь/coastal_cliff_02 /путь/fern_02 /путь/rock_moss_set_01`. Девять карт terrain берутся из наборов Poly Haven 1K, перечисленных в том же реестре. После сознательной пересборки обновить хеши и импорт, проверить кадры.
- Кадры и замер: `"$GODOT_BIN" --path godot --script res://tests/gorge_review.gd -- --test-mode --output=/tmp/gorge-art`. Шесть фиксированных камер, включая вид с берега; 1280×800, 3 секунды прогрева на ракурс, 180 кадров для среднего FPS, медианы/p95, draw calls и render CPU. `performance.json` указывает устройство и renderer. GPU time равен null, когда backend не возвращает замер. Отключение VSync не исключает ограничение compositor/ProMotion macOS.
- Сравнение до/после делается последовательно без Blender/тестов в фоне. Для «до» использована отдельная временная копия Godot-проекта с файлами HEAD и тем же измерительным скриптом; рабочие ветки и основная копия не переключались.
- Приёмка среза: `npm test` (pipeline, unit, server, native:lint, реальный native smoke). Smoke дополнительно проверяет декодирование 68 записей, наличие сканированного декора, включение Ambience у водопада и остановку при телепорте.
- В worktree `.native-run` заменён с локального симлинка на игнорируемый отдельный каталог: логи, тестовые кадры и локальная БД не пишутся в основную копию. `node_modules` остаётся исходным симлинком. Ни тот, ни другой путь не коммитится.

Полный native:verify под Node 22, экспорт Windows/macOS, touch и реальные Android/iOS в рамках этого прохода не выполнялись; успешный npm test не означает готовность публичного релиза.

Шейдер земли ограничен 16 sampler2D для базового мобильного бюджета. Dry Ground в смешанном грунте использует только albedo; normal/AO/roughness берутся из лесной почвы и мха, остальные исходные карты набора сохранены в реестре для воспроизводимости. Это не независимый физически точный PBR-слой гравия.

### Второй проход маршрута: прибытие → бой → водопад

Русло и бассейн теперь одна индексированная поверхность с шагом 1 м: её диагонали согласованы с 4-метровой сеткой земли.
