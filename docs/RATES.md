# Рейты сервера

Коэффициенты (рейты) — множители наград и расходов, которыми владелец сервера задаёт темп
игры: от классики ×1 до быстрого старта ×10. Считает их **только сервер**; клиент получает
итоговые значения в приветственном кадре `hi` и лишь показывает их строкой в меню игры.

Значения по умолчанию равны единице и повторяют текущий баланс один в один — это
проверяется тестом `tests/rates.test.js` для всех мобов, предметов и рецептов.

- Правила и пределы: `src/rates.js` (чистый модуль, без файловой системы).
- Источник настроек: `server/rates.js` → `server/rates.json` + переменные окружения.
- Точки применения: `server/sim/mobs.js`, `server/sim/party.js`, `server/sim/player.js`.

## Таблица коэффициентов

| Ключ | Переменная окружения | Пределы | На что влияет |
|---|---|---|---|
| `xp` | `RATE_XP` | 0.1…100 | опыт за убийство моба; умножается **до** дележа в группе |
| `sp` | `RATE_SP` | 0.1…100 | SP за убийство моба; тоже до дележа |
| `coins` | `RATE_COINS` | 0.1…100 | монеты, выпадающие с моба |
| `dropChance` | `RATE_DROP_CHANCE` | 0.1…100 | шанс выпадения вещей; итоговый шанс не превышает 100 % |
| `dropAmount` | `RATE_DROP_AMOUNT` | 1…100, целое | сколько штук каждой выпавшей вещи |
| `craftCost` | `RATE_CRAFT_COST` | 0.1…100 | монеты и материалы в рецептах изготовления |
| `enchantChance` | `RATE_ENCHANT_CHANCE` | 0.1…10 | шанс успеха заточки выше безопасной ступени (+3) |
| `sellPrice` | `RATE_SELL_PRICE` | 0.1…100 | сколько NPC платит за вещь |
| `buyPrice` | `RATE_BUY_PRICE` | 0.1…100 | сколько NPC просит за товар |
| `respawn` | `RATE_RESPAWN` | 0.1…100 | скорость возрождения мобов: время делится на множитель (×2 — вдвое быстрее) |
| `partyBonus` | `RATE_PARTY_BONUS` | 1…2 | надбавка к XP/SP за каждого дополнительного участника группы |

Правила, которые нельзя обойти рейтами:

- **Гарантированный дроп остаётся гарантированным.** Шанс 1 (печать Короля-лича, эктоплазма
  с босса) не понижается даже при `dropChance` меньше единицы.
- **Награда не обнуляется.** Опыт и SP за убийство всегда не меньше 1, материал в рецепте —
  не меньше 1, товар у NPC — не дешевле 1 монеты.
- **Непродаваемое не продаётся.** Стартовые вещи и печати остаются с нулевой ценой выкупа
  при любом `sellPrice`.
- **Суммы в группе сходятся.** Множители применяются до дележа, доли остаются целыми, сумма
  долей точно равна награде (остаток раздаётся по одной единице).
- **Клиент ничего не считает.** Витрина торговца показывает базовые цены каталога; фактическую
  сумму сделки считает и называет сервер («Куплено: … за N мон.»). При `buyPrice`/`sellPrice`
  не равных единице это расхождение видно игроку — ставьте их осознанно.

## Как задать

Файл `server/rates.json` (значения по умолчанию — все единицы):

```json
{ "rates": { "xp": 3, "sp": 3, "coins": 3, "dropChance": 2, "respawn": 2 } }
```

Другой путь к файлу — переменная `RATES_FILE`. Переменные окружения сильнее файла:

```bash
RATE_XP=5 RATE_SP=5 RATE_COINS=3 node server/server.js
```

В `docker-compose.yml` или unit systemd их задают в `environment`. `server/rates.json` попадает
внутрь образа при сборке, поэтому на проде менять рейты удобнее переменными окружения —
иначе нужен новый образ. Настройки читаются один раз при старте; после правки сервер нужно
перезапустить.

При старте сервер пишет итог в журнал:

```
realms-ws :8790, аккаунтов: 12, мобов: 225
[rates] Рейты сервера: опыт ×5, SP ×5, монеты ×3 · источник: rates.json + RATE_XP, RATE_SP, RATE_COINS
```

Ошибки настроек не роняют сервер: нечитаемый или битый файл, неизвестный ключ, строка вместо
числа и выход за пределы дают предупреждение `[rates] …` и подстановку рабочего значения.

## Примеры конфигураций

**×1 — классика (по умолчанию).** Файл можно не трогать; баланс описан в
[ECONOMY_BALANCE.md](ECONOMY_BALANCE.md).

```json
{ "rates": { "xp": 1, "sp": 1, "coins": 1, "dropChance": 1 } }
```

**×3 — комфорт.** Рабочий вечер укладывается в заметный прогресс, экономика остаётся узнаваемой.

```json
{ "rates": { "xp": 3, "sp": 3, "coins": 3, "dropChance": 2, "respawn": 1.5, "partyBonus": 1.1 } }
```

**×10 — быстрый старт.** Для теста контента и коротких сезонов: уровень 25 достигается за
полторы сотни убийств, заточка и крафт щадящие.

```json
{ "rates": { "xp": 10, "sp": 10, "coins": 10, "dropChance": 5, "dropAmount": 2,
             "craftCost": 0.5, "enchantChance": 1.3, "respawn": 3, "partyBonus": 1.2 } }
```

## Как посчитать влияние

`npm run native:economy` принимает те же коэффициенты:

```bash
npm run native:economy -- --rates=5            # опыт/SP/монеты/шанс дропа ×5
npm run native:economy -- --rate-xp=3 --rate-coins=2
npm run native:economy -- --compare            # таблица x1/x2/x5/x10 до 25 и 40 уровня
```

Равномерные множители (опыт/SP/монеты/шанс дропа), путь без смертей и расходов:

| Рейты | Убийств до 25 | Монеты к 25 | SP к 25 | Убийств до 40 | Монеты к 40 | SP к 40 |
|---|---:|---:|---:|---:|---:|---:|
| ×1 | 1 446 | 91 582 | 72 357 | 15 144 | 1 803 832 | 333 162 |
| ×2 | 728 | 92 047 | 72 722 | 7 581 | 1 805 297 | 333 918 |
| ×5 | 300 | 93 803 | 74 050 | 3 049 | 1 811 928 | 337 805 |
| ×10 | 156 | 97 245 | 76 760 | 1 535 | 1 820 995 | 343 500 |

Монеты «к уровню» почти не меняются: убийств нужно во столько же раз меньше, во сколько
больше падает с каждого моба. Рейт монет ускоряет доход **за час игры**, а не за уровень —
чтобы снаряжение обгоняло уровень, поднимайте `coins` и `dropChance` сильнее, чем `xp`.
Запись в `docs/ECONOMY_BALANCE.md` (`--write`) разрешена только при рейтах ×1: канонический
файл описывает классический баланс.

## Чего в игре нет и что рейтами не настраивается

- **Спойла нет** — нет ключа `spoil`. Разбор трупов и материализация не реализованы.
- **Квестов, рыбалки, манора, осад нет** — соответствующих рейтов тоже нет.
- **Случайной неудачи крафта нет**: изготовление гарантированное, поэтому есть `craftCost`,
  но нет `craftSuccess`.
- **Заточки умений за XP/SP нет** (см. PROGRESSION.md), `enchantChance` относится только к
  заточке вещей.
- **Потеря опыта при смерти** (`xpLossOnDeath`), карма, цена телепорта и очищения кармы
  рейтами не управляются — это отдельная тема, если понадобится.
- **Рынка между игроками нет**, поэтому `sellPrice`/`buyPrice` касаются только торговца NPC.
